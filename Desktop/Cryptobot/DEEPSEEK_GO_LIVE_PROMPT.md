## КАК РАБОТАЕТ АЛГОРИТМ (не сломай эту логику)

1. Коллектор держит WebSocket к Binance, получает свечи 1h по 17 ликвидным парам.
2. На закрытии каждой часовой свечи движок SMC анализирует 500 последних свечей.
3. Ищет: свинг-точки, сломы структуры (BOS/CHoCH), имбалансы (FVG), ордер-блоки
   с импульсом, снятия ликвидности (sweep), считает режим рынка (TREND/RANGE/CHOP)
   и биас старшего таймфрейма (4h).
4. Считает confidence 0-100. Сигнал рождается при confidence >= 50 И RR >= 3:1.
5. Гейты перед публикацией: макро-блэкаут (±60 мин вокруг FOMC/NFP), BTC-поводырь
   (медвежья структура на 4h И 1d => все лонги блокируются), CHOP-вето.
6. Сигнал -> БД -> Redis pub/sub -> Telegram + SSE на дашборд.
7. Пользователь подтверждает вручную. Бот НЕ торгует сам — это принципиально.
8. При исполнении: размер позиции считается от риска 2% депозита, ордер ставится
   атомарно со стопом и тейком, лимиты портфеля (макс 5 позиций, дневной стоп 5%).

## ЧТО УЖЕ СДЕЛАНО — НЕ ПЕРЕДЕЛЫВАЙ

- Fernet-ключи: fail-fast при пустом ENCRYPTION_KEY (иначе ключи бирж умирают при рестарте)
- Геометрия сигналов: для SELL тейки НИЖЕ входа, для BUY выше (было сломано)
- Коллектор: все 17 пар параллельно через asyncio.gather, буфер свечей в памяти
- Биллинг: раздельные прайсы USD/RUB, проверка expires_at, expiry-цикл
- Исполнение: PENDING -> ордер -> OPEN, атомарный SL/TP, PnL и комиссии при закрытии
- Доступ: /signals под авторизацией, free видит с задержкой 24ч, rate-limit на auth
- Paper-режим: исполнение без ключей биржи
- Market Context Engine + Smart DCA
- 48 pytest-тестов

## ТВОИ ЗАДАЧИ ПО ПРИОРИТЕТУ

### БЛОК 1 — БЕЗ ЭТОГО НЕЛЬЗЯ ВКЛЮЧАТЬ РЕАЛЬНЫЕ ДЕНЬГИ

**1.1. Прогнать честный бэктест и дать вердикт по каждой паре.**
Напиши CLI-скрипт backend/scripts/run_backtest.py, который:
- качает историю 1h за 2 года по всем 17 парам из TRADE_SYMBOLS (ccxt, постранично)
- прогоняет SMCStrategy.backtest() по каждой паре
- печатает таблицу: пара, число сделок, win rate, expectancy_pct, profit factor,
  max drawdown, суммарные издержки, число истёкших сигналов
- делает walk-forward: первый год — калибровка, второй — проверка
- сохраняет результат в CSV и JSON
Критерий готовности: получен отчёт, где по каждой паре видно, положительное ли
математическое ожидание ПОСЛЕ издержек. Пары с отрицательным ожиданием ты должен
предложить исключить из TRADE_SYMBOLS. Не приукрашивай результаты: если стратегия
убыточна — так и напиши, это важнее, чем красивый отчёт.

**1.2. Поддержка Bybit TESTNET.**
Сейчас исполнение всегда идёт на реальную биржу. Добавь:
- поле testnet в ExchangeKeySet (schemas/user.py) и в хранимые ключи
- в signals.py и invest.py при создании ccxt-клиента: если testnet, вызывать
  exchange.set_sandbox_mode(True)
- в ответах API возвращать флаг testnet, на фронте показывать бейдж «TESTNET»
Критерий: пользователь может подключить testnet-ключи и торговать без реальных денег.

**1.3. Аварийный стоп (kill switch).**
Добавь глобальный и пользовательский рубильник:
- модель UserTradingSettings или поле trading_enabled в User
- POST /api/v1/trading/kill-switch — мгновенно запрещает новые входы
- опция «закрыть все открытые позиции рыночными ордерами»
- глобальный флаг в Redis (админский), который блокирует исполнение для всех
- кнопка на дашборде, красная, с подтверждением
Критерий: при включённом стопе любой вызов execute возвращает 403 с понятным текстом.

**1.4. Проверка прав API-ключа при сохранении.**
При добавлении ключей Bybit вызвать приватный эндпоинт и убедиться, что:
- ключ валиден (иначе 400 с понятной ошибкой)
- у ключа НЕТ права на вывод средств; если есть — вернуть 400 и потребовать
  пересоздать ключ без права withdrawal
Критерий: невозможно сохранить ключ с правом вывода.

**1.5. Синхронизация позиций с биржей.**
Сейчас позиция помечается закрытой только при ручном закрытии через наш API.
Если стоп или тейк сработал на бирже — в нашей БД трейд навсегда висит OPEN.
Реализуй фоновый цикл (в scheduler.py, раз в 60 сек):
- для каждого пользователя с открытыми трейдами дёргать fetch_closed_orders /
  fetch_my_trades по символам
- если позиция закрыта на бирже — записать exit_price, pnl, fee, closed_at,
  статус CLOSED и отправить уведомление в Telegram
Критерий: сработавший на бирже стоп отражается в истории и PnL в течение минуты.
Осторожно с приватными ключами: расшифровывать только внутри цикла, не логировать.

### БЛОК 2 — ДОВЕРИЕ И ПРОЗРАЧНОСТЬ

**2.1. График с разметкой сигнала.**
Библиотека lightweight-charts (TradingView, бесплатная, MIT).
- эндпоинт GET /api/v1/market/candles?symbol=X&timeframe=1h&limit=200 (из Redis-кэша)
- компонент на дашборде: свечи + горизонтальные линии entry/SL/TP + зоны FVG и OB
  из signal.metadata
Критерий: по клику на сигнал открывается график с разметкой.

**2.2. Страница track record.**
- эндпоинт GET /api/v1/analytics/track-record: все сигналы за период и их исход
  (определяется по истории цен: задет SL или TP первым), агрегаты — win rate,
  средний RR, expectancy, разбивка по парам
- публичная страница на фронте (без авторизации, read-only)
Критерий: страница показывает честную статистику, включая убыточные сигналы.

**2.3. Мониторинг и алерты.**
- GET /api/v1/health/detailed: статус коллектора (время последней свечи по каждой
  паре), Redis, БД, актуальность market context
- если коллектор молчит > 15 минут — алерт админу в Telegram
- подключить Sentry (SENTRY_DSN в конфиге), если DSN задан
Критерий: остановка коллектора приводит к сообщению админу за 15 минут.

### БЛОК 3 — ПОДГОТОВКА К ЗАПУСКУ

**3.1. Слияние двух Telegram-ботов.**
В проекте два бота: Desktop/Cryptobot/bot.py (2982 строки, GPT-4o + Google Sheets,
работает) и backend/app/bot/ (модульный, DeepSeek + PostgreSQL). У них РАЗНЫЕ цены
($25/$199 lifetime против $29/$79) — это конфликт. Перенеси в backend-бот:
приём UID реферала, оплату CryptoCloud, vision-разбор скриншотов. Затем отключи
корневой bot.py. Единый прайс-лист — из app/models/subscription.py.

**3.2. Автоверификация Bybit-рефералов.**
Таблица referral_claims(user_id, exchange, uid UNIQUE, status, deposit_usd,
verified_at). Часовая задача дёргает Bybit Affiliate API, проверяет привязку UID и
депозит >= $150, при успехе выставляет user.referred_by. Это ЕДИНСТВЕННОЕ место,
где referred_by может записываться — сейчас это дыра: любая строка даёт бесплатный доступ.

**3.3. Деплой.**
Дополни docker-compose: nginx с HTTPS (certbot), healthcheck для backend,
автобэкап PostgreSQL в S3 раз в сутки с ротацией 30 дней. README с пошаговой
инструкцией развёртывания.

## ЖЁСТКИЕ ТРЕБОВАНИЯ — НАРУШАТЬ НЕЛЬЗЯ

1. НИКОГДА не делай так, чтобы бот торговал без подтверждения пользователя.
2. Позиция НИКОГДА не должна существовать без стоп-лосса. Если биржа отклонила
   ордер со стопом — не открывай позицию вообще.
3. НИКОГДА не логируй расшифрованные API-ключи, секреты, токены.
4. Все изменения покрывай тестами. Существующие 48 тестов должны остаться зелёными:
   cd backend && python -m pytest tests/ -q
5. Не убирай существующие защиты: fail-fast на ENCRYPTION_KEY, лимит 5 позиций,
   дневной стоп 5%, макро-блэкаут, BTC-гейт, требование RR 3:1.
6. Не добавляй в сигнальный движок нейросети и внешние AI — он должен оставаться
   детерминированным. AI используется только для объяснений текстом.
7. Каждое изменение схемы БД — отдельной alembic-миграцией, не правь существующие.
8. Если находишь баг за пределами своей задачи — не молчи, опиши его отдельно.
